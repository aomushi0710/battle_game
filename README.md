# manipulator
確率操作型コマンドバトルゲーム
<img src="https://i.imgur.com/px6IBx5.png" title="バトル画面">

### 公開URL
[動作紹介動画(Youtube)](https://youtu.be/mh3FtvL_wRU)

### 工夫した点
- モンスターや技など、あらゆる構造化データをカスタムリソースとして管理し、高い再利用性と拡張性を実現
- 上記カスタムリソースを設定することで動的に色や画像、テキストなどの表示が変更されるUI
- 以下の様々な機能を備えた、自作ダイアログシステム
  - 会話中の話者名の表示(色の指定も可)
  - ダイアログボックス内の画像表示
  - ボタン選択肢による会話の分岐
  - 会話からバトルへの移行フラグ
  - バトルの勝敗による会話の分岐
- マップ画面からバトル画面へのスムーズな移行アニメーション
- 以下の様々なプレイヤーの入力に対応した、技の出現確率調整システム
  - シークバーをマウスでドラッグする
  - シークバー上でマウスホイールを回転させる
  - 上下矢印ボタンをクリックして微調整を行う
  - テキストボックスに直接数値を入力する
- 現在の技の出現確率の全体像が一目で分かる動的生成円グラフ表示の実装
- 複数属性を持つモンスター及び技の、属性表示部分
- 技のおまかせ選択システム
- 以下のカスタマイズ設定が可能なデッキ自動生成システム
  - プレイヤーのデッキ生成時、自動で利用可能なモンスターとそのレベルを設定
  - 敵のデッキ生成時、モンスターのIDを指定して範囲内のモンスターのみに制限
  - 敵のデッキ生成時、最小レベルと最大レベルを指定して範囲内のレベルをランダムで設定
- awaitによる非同期処理を用いたバトルロジックの構築
- デッキのセーブ機能(手動)及びゲームのセーブ機能(手動・オート)

### 改善したい点
- 過去に記述した、コーディング規則に従えていない一貫性のないコード
- 内部バトルロジックとUI描写ロジックの機能分割
- マップ上で表示されているキャラクターが1枚絵であるため、上下左右どちらを向いているかわからない
- 速度ゲージが同時に溜まった場合の判定(現在は常にプレイヤーの行動を優先させて解決)

### 既知のバグ
- デッキ画面において、第二形態や第三形態をプレビュー表示したまま画面を閉じると、該当する形態のままバトルを開始できてしまう
- 敵が使用する「味方単体」を対象とした技が、死亡したモンスターを発動先に指定してしまう
- バフ及びデバフを重ね掛けした場合、追加されるターン数が本来より1ターンだけ長くなってしまう
- 4桁以上のダメージを出した時、ダメージ表記の文字が崩れる
- メニューに表示される所持コイン数の反映が遅れているバグ
- チュートリアル時に表示されるボタンが「終わる」ではなく、バトル時に表示される「逃げる」になっている
- 「次に行動するモンスター」枠に表示されているモンスターが進化した時、枠の表示が進化後のモンスターに変化しない
